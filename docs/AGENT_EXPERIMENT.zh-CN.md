# 基础协议的独立节点 agent 实验

## 范围

Alice 先提交加密订单，Bob 独立提交自己的订单或转发公开密文。节点只看协议公开元数据及自己的历史。节点模型不获知谁是信息领先者、谁是攻击者，也没有私聊或操纵其他节点的工具。

协议流程：加密提交 → 持久化收录承诺 → 签名完整名单 → 共同登记并追加队列 → 锁定服务前缀 → 发布解密份额 → 解密并执行。检查承诺、纳入、处理和成交时必须分别统计。

每轮所有符合条件的名单并集订单采用同一套确定性占位顺序（公开 owner、nonce、密文 ID）。名单出现次数不决定订单的排序资格或优先级。这个占位顺序用于一致执行，不是先发先执行保证；批内公平排序不在当前实验范围。

## 角色与故障

- 默认实验为 8 节点，f=2，收录签名门槛 q=6，解密门槛 t=3。
- 0%、25%、50%、100% 表示分配的偏离角色比例；50% 和 100% 超出 f=2。
- 接单动作：正常、拒收、延迟。
- 名单动作：包含自己的全部已接单订单，或由在线模型明确选择其中的 ID。
- 解密动作：正常发布自己的授权份额、扣留自己的份额。
- Bob 只能用自己的钱包交易或转发公开包，不能修改用户签名、解密密文或指挥节点。
- 不假设工资、gas 收益、押金罚没或理性均衡。测试目标是检验允许的恶意偏离，不解释经济动机。

## 两个入口

`harness/agent_experiment.py` 在计时前生成受限策略，然后由独立规则 agent 执行；支持 `omission`、`refusal`、`delay`、`withhold` 和 `mixed`。这是固定策略压力测试。

`harness/online_experiment.py` 在真实消息到达时调用模型，记录实际观察、决定、简短自述和耗时。见[在线说明](ONLINE_AGENT_PILOT.zh-CN.md)。模型可以选择正常动作；返回错误、超时或无效动作必须单独记录。

运行脚本压力测试（不调用模型）：

```sh
./scripts/go.sh build -o bin/pinocchio ./cmd/pinocchio
.venv/bin/python harness/agent_experiment.py \
  --binary "$PWD/bin/pinocchio" --backend scripted \
  --fractions 0,25 --scenarios none,race --profile omission \
  --out "$PWD/runs/base-agent-test-01"
```

## 记录与结论边界

分别统计有效承诺数、是否登记、锁序和执行时刻、成交份额、签名漏报证据、模型/接口失败。CPU/RSS 为本机抽样；客户端 HTTP 请求字节不含完整网络通信开销。固定价库存市场不构成真实三明治利润测试。

此前 39 次矩阵和两次在线模型实验使用了错误引入的排序扩展，其项目结论已撤回。原始日志归档保留，不能直接作为基础协议的保护或漏洞证据，也不能只改报告标题后重新使用。当前基础协议的正式实验结果须另行运行和报告。
