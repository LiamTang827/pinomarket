# 基础协议的在线节点 agent

## 当前状态

在线模型接口保留，已移除外加排序机制及虚报序号工具。此前在线试验结论已撤回，见[范围纠正](SCOPE_CORRECTION.zh-CN.md)。当前没有把旧结果改写成基础协议实验结果。

## 参与者能看什么、做什么

节点模型只获得本节点公开元数据、轮次、高度、额度、已接单 ID、自己的历史和锁定后的服务名单。用户身份替换为匿名标识；订单明文、密钥和秘密份额不提供给模型。模型不知道其他节点的角色或策略，没有 agent 私聊工具。正常协议传播与共识通信仍然存在。

接单时选正常、拒收或额外延迟 0–1500ms；准备名单时选正常包含全部，或明确选择自己已接单快照中的 ID；锁序后选正常发布授权份额或扣留。Python 与 Go 分别检查动作边界，禁止模型改变排序规则、其他节点的签名或用户密文。

Bob 在 Alice 已开始广播后观察公开市场与密文元数据，用自己的余额选择买 1–10 份和额外等待 0–1000ms。他无法获知 Alice 的隐藏数量或指挥节点。

默认 8 节点中 2 个具有独立 Byzantine 测试目标，其余 6 个按诚实规则处理。模型被要求检验承诺纳入和处理进展，允许正常动作。没有经济收益函数，不把测试目标解释为真实节点的逐利动机。

## 批次与顺序

本轮有效完整名单的并集共同登记；不设置每笔订单的观察票数排序门槛。批内沿用公开 owner、nonce、密文 ID 的确定性占位顺序，登记轮间追加 FIFO 队列；服务前缀先锁定再解密。该占位顺序没有按实际接收时间公平排序的承诺。

模型可能较慢，因此可提前准备自己的名单决定，正式名单仍在接单窗口结束后签署。准备之后的新接单自动加入，避免旧快照意外漏报。该调度是实验接口安排，需要在结果里记录。

## 运行方式

下面会使用已保存的模型连接并消耗模型额度；这是新的基础协议试验，输出目录必须不存在。

```sh
./scripts/go.sh build -o bin/pinocchio ./cmd/pinocchio
.venv/bin/python harness/online_experiment.py \
  --binary "$PWD/bin/pinocchio" --state-dir "$PWD/.local/chatgpt" \
  --out "$PWD/runs/base-online-pilot-01" \
  --window-blocks 100 --prepare-blocks 50 --deadline 130
```

默认最多两次在线搜索，每个模型节点每次最多 8 次调用，Bob 每次 1 次。窗口单位为共识区块；放大窗口是为模型留出思考时间，不代表生产延迟。

每次另跑诚实动作等待对照，复用 Bob 的决定和记录的回调耗时。回放扣除已经发生的排队时间。独立网络的调度不同，不能称为完全相同的轨迹。旧扩展的记录不允许作为基础协议的回放输入。

## 结果怎么读

- `result.json`：承诺、登记、位置、处理、成交、证据和提交错误分别记录。
- `node-N-decisions.jsonl`：实际公开观察、匿名模型输入、决定、简短自述与耗时。
- `node_list_effects`：结果字段，检查选择是否提交、名单是否被选中及包含哪些订单。
- `agents-summary.json`、`model-calls.jsonl`：实际调用和失败次数。
- `state-public.json`、`audit.json`：最终状态和真实共识重放审计。

模型错误和超时属于接口/实验失败，不能算作协议攻击成功。简短自述不是完整内部思考。没有发现反例不能证明安全；固定价成交份额不是金融利润，少量订单不能测吞吐上限。原始网络目录含演示私钥，保存在忽略的 `runs/` 下。
