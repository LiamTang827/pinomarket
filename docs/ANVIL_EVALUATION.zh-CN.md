# Anvil 本地对照实验

Alice 用 100,000 单位报价资产购买同一个池子的份额。在明文市场，Alice 的交易先提交到待处理池。实验用本地预设交易重现 Bob 把买单放到 Alice 前面的抢跑，以及 Bob 买入、Alice 买入、Bob 卖出的三明治。脚本逐笔读取 Anvil 回执，核对实际执行位置。

保护组把 Alice 的交易作为密文发给五个 Go 节点。CometBFT 确认服务名单及其顺序后，节点才发布解密份额。三个有效份额可恢复正文。中继向节点收集四份独立的 EVM 批次签名，任意账户都可提交这份批次。合约核验签名、链 ID、合约地址、批次号、锁定摘要和订单数组，逐笔执行。合约采用签名委员会信任模型。

两套合约使用相同的恒定乘积公式和整数取整。每个池子的起始储备为 1,000,000／1,000,000，每个交易账户起始报价资产为 1,000,000。池子没有手续费，链上交易仍消耗 gas。保护组只有批次入口。Bob 可以提交自己的有效订单，参与锁序前的竞争。

## 复现

安装 [Foundry](https://getfoundry.sh/introduction/installation/)、Python 3、Go 和 C 编译器。在仓库根目录运行下面的命令。脚本启动新的回环地址开发链和五个本机节点，结束后清理临时进程和密钥。JSON 输出路径须为新文件。

```sh
./scripts/go.sh test ./...
forge test
python3 scripts/anvil-experiment.py --workloads 1 3 6 --repeats 3 \
  --output runs/anvil-experiment.json
```

Foundry 配置固定 Solidity 0.8.24、Paris EVM 目标和 200 次优化。已有本地编译器时，可以传入 `--solc /path/to/solc`。Go 侧的受理窗口为 12 个共识块，CometBFT 的最低区块间隔配置为 300 ms。Anvil 由脚本手动出块。

## 实测攻击对照

| 场景 | 链上实际执行 | Alice 收到的份额 | Bob 的结果 |
| --- | --- | ---: | --- |
| 明文，无攻击 | Alice 买入 | 90,909 | 未交易 |
| 明文，抢跑 | Bob 买入 → Alice 买入 | 75,757 | 仍持有份额，尚未兑现卖出收益 |
| 明文，三明治 | Bob 买入 → Alice 买入 → Bob 卖出 | 75,757 | 完成卖出，报价资产增加 18,032，gas 另计 |
| 密文锁序，尝试插单 | 仅 Alice 的签名批次执行 | 90,909 | 插单和绕过入口的请求回退，报价资产余额无变化 |

Alice 在三组明文场景均先提交，脚本在出块前能从本地待处理池读到她的明文调用。抢跑和三明治均让她少收到 15,152 份，约 16.67%。保护组的单笔批次只锁定 Alice。另一组锁定三笔订单，专门检查中继调换和删去订单的请求。尝试重放、复制签名凑数、复用原签名插单或重排均被拒绝。若 Bob 在明文揭示之前独立提交自己的密文，他仍会参与正常排序。

## 怎么看输出

| 字段 | 含义 |
| --- | --- |
| `attack_cases` | 三种明文场景、只锁定 Alice 的保护场景、三笔已锁定交易的重排检查 |
| `receipts_in_block_order` | 明文交易实际回执，包含区块号、交易位置和 gas |
| `rejected_attempt_receipts` | 插单、重排、替换、重放等请求的本地回执 |
| `settlement_swap_events` | EVM 实际执行的订单，按合约事件顺序排列 |
| `workload_summary` | 每组重复次数、延迟样本、延迟分位数、有限批次完成率和 gas／订单 |
| `application_http`、`comet_p2p`、`evm_batch_calldata_bytes` | 应用 HTTP 消息体、CometBFT 发送消息负载、提交合约的数据，三者分开计量 |
| `client_command_cpu_ms`、`go_timings` | 钱包进程 CPU 时间，及节点重验解密与批次签名的局部墙钟时间 |

确认延迟从开始提交到收到 Anvil 回执。工作负载以串行提交的有限批次执行，完成率以批次订单数除以从首次提交到最后回执的墙钟时间。手动出块排除了真实链的出块等待与最终性。应用层和共识通信按各自的计数器边界统计，TCP、HTTP 头和传输封包另计。Gas 是链上执行量，真实支付取决于部署链和 gas 价格。

## 代码阅读顺序

1. [实验脚本](../scripts/anvil-experiment.py) 中的 `direct_case` 和 `protected_case` 分别组织两个对照组。
2. [Go 批次桥接](../internal/live/evm.go) 从本节点已提交的服务状态重验开包并签署序列。收集端按摘要匹配签名。
3. [EVM 市场合约](../evm/src/Market.sol) 的 `swap` 是明文入口，`executeBatch` 是受保护入口。它们共用 `_swap`。
4. [合约测试](../evm/test/Market.t.sol) 验证合约规则，实验脚本另外验证跨进程和链上回执。

## 适用范围

- EVM 合约强制该市场按签名序列执行。可移植性来自普通 Solidity、ABI 与 `ecrecover`。接入存量 DEX 需要将其可执行入口纳入同样的约束，还需考虑流动性、授权和部署成本。
- 保护从密文受理和服务锁定开始。网络入口审查、全局先到先得、独立提交者的成交竞争、跨市场 MEV、底层区块是否及时纳入批次仍需单独评估。
- 当前入口与时钟是软件模拟。真实 TEE、可信网卡、远程证明、跨地域延迟及高负载下的可用性尚需验证。
- EVM 适配按一次实验绑定一个市场。Go 桥目前会拒绝签署含无效密文或混合目标的整批。合约可记录余额、最小输出和 nonce 等业务检查失败。生产版本需要完善无效负载跳过、批次恢复与重试，以及两条链的状态对账。
