# 当前设计与实现范围

状态：v0.3 已实现真实本地多进程协议，v0.2 单进程模拟保留为基线。本文说明实现边界，不是形式化安全证明；具体消息和命令见 [本地协议说明](LIVE_PROTOCOL.zh-CN.md)。

## 三个目标

1. 在内容隐藏时，给订单明确、可核验的收录义务。
2. 在发布解密份额前，共同确认处理名单与顺序，并按该顺序执行。
3. 根据成员自己签署的声明核验违规，保留可独立检查的记录。

不把仿真器隐藏的全局信息当成现实验证者可取得的证据，也不把“没有成交”当成“协议没有处理”。

## 两种模式

- **v0.3 `network`**：实际多个 OS 进程、本机网络通信、CometBFT 共识、真实门限加密与可验证解密份额、磁盘持久化、共识提交与区块重放审计。
- **v0.2 模拟**：单进程虚拟调度，真实 Ed25519 与 AES-GCM，但共同确认和密钥释放由理想组件实现；用于精确复现消息调度和业务案例。

两个模式共用最小市场规则。模拟报告审计和真实网络审计是不同入口，不应混为一谈。

## 实际基础流程

| 阶段 | 已实现的行为 | 保护边界 |
|---|---|---|
| 开窗 | 共识确定本轮窗口及每节点接单额度 | 窗口按区块高度，不是现实接收时间证明 |
| 提交 | 用户签名订单，AES-GCM 加密正文，再门限加密随机 AES 密钥并签名密文包 | 身份、轮次等必要字段仍公开 |
| 准入承诺 | 节点校验并持久化密文和签名承诺，返回用户并转发公开收据 | 承诺约束本地完整清单，不立即分配全局位置 |
| 完整清单与登记 | 共识提交足够多份不同节点的完整清单，合并去重、确定同轮顺序并追加队列 | 同轮排序是确定规则，不证明先到先得；承诺签名数达标是纳入的充分条件，不是所有纳入订单的必要条件 |
| 服务锁序 | 共识最终确认有限长度的队首名单与顺序 | 后轮订单不能插到已登记队首前面；进度依赖共识和解密可用性 |
| 解密与执行 | 节点根据本地已提交锁序状态生成自己的份额，份额提交并验证后重构密钥、按序处理 | 成交仍受余额、限价和库存约束；足够多成员串谋仍可提前泄密 |
| 证据 | 同节点的有效承诺与遗漏该订单的签名完整清单组成遗漏证据，验证后记入共同状态 | 尚未自动罚没、扣押金或发放赔偿 |

## 有限队列与默认参数

默认 `n=5`、`f=1`、承诺人数 `q=4`、解密门限 `t=3`。四份承诺与四份登记清单的成员集合至少交叠三个成员，最多一个恶意成员时仍有诚实交叠。纳入推理同时要求客户端没有用同一身份与命令编号提交冲突密文、诚实成员履约、协议按假设推进。

全局队列上限默认 30，一次服务最多 2 笔。本轮开始时，设尚未处理的队列订单数为 `U`，每节点接单额度固定为：

```text
M = floor((Qmax - U) / n)
```

服务中的订单在执行完成前仍计入 `U`。保守地为每个节点预留 `M` 个位置，避免把各节点不同清单的并集塞爆队列。它不是实际吞吐量公式；多个节点对同一订单签名也只登记一笔。

同轮顺序目前按公开的 `(owner, nonce, packet ID)` 确定。这是可复现的占位规则，可被身份选择影响，未解决公平批内排序。当前不实现孔多塞循环相关排序。

## 最小市场

- 一笔事先锁定 10 份库存的 YES 卖单，每份 60 分。
- 三名买家各有初始余额；买入与卖家撤单走同一加密处理流程。
- 支持成交、部分成交、余额不足、限价不满足和无库存等确定结果。
- 买方资金执行时检查，尚无提交前资金预留或隐私余额证明。
- 不包含真实赛事预言机、代币发行、AMM、外部链资金结算或完整交易所。

## 证据与没有覆盖的行为

v0.3 已实现承诺遗漏证据：同主体、同上下文、同轮的签名承诺，与声称完整却遗漏该密文的清单相矛盾。v0.2 模拟还提供冲突清单检查。超额承诺、承诺前的隐藏等待、接受序号和摘要链是后续研究方向，尚不算完成。

以下情形本身不判为说谎：

- 不同成员看到不同的接收顺序。
- 用户发出请求，但尚无节点签署的承诺。
- 消息超时，无法区分故障、延迟或故意忽略。
- 订单按规定处理，但因余额、限价或库存失败。

## 信任与部署边界

采用 CometBFT 和 Shutter 现有组件，不宣称自行发明共识或门限密码方案。运行时各节点只加载自己的私钥和份额；但初始化器通过本地中继运行逐成员 DKG，配置过程中可接触全部输出份额。因此当前仍信任初始化环境，不能声称已完成独立的认证分布式 DKG 部署。

进程同机、同 OS 用户，接口只允许本机回环地址；没有主机级隔离或公开网络部署。缺少足够共识票数或解密份额会阻止进度。证据不自动带来惩罚，签名也不证明节点的真实首次收包时间。目前没有 gas、经济激励、期限保障或现实世界先知者优先保证。

## 当前核验方式

已跑通真实五进程案例：签署承诺的节点重启、一个验证节点离线继续处理、重新加入后追赶且不重复执行、承诺遗漏证据。审计器核验真实共识提交签名、重放区块、验证门限解密结果，并独立核算余额和库存。

这些功能结果可作为后续实验的基础。性能、通信量、攻击收益、对照方案和新颖性需要另行定义并测量，不能从“测试通过”直接推导。
